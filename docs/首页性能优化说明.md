# 首页性能优化说明

## 本次改造

1. **导航数据缓存**：MySQL 成功快照在当前 Node 进程内缓存 30 秒，并发冷请求合并为一次数据库加载。TTL 从加载开始计算。失败不缓存，不用过期数据掩盖数据库异常。
2. **发布失效**：站点审核发布事务提交成功后清除当前进程缓存；旧在途请求不能回填失效后的缓存。其他进程及外部数据库写入最多在 TTL 窗口内命中旧快照；已在途请求可能返回原快照。多实例要求立即一致时需要共享失效通知，当前没有引入 Redis。
3. **减少首批渲染**：所有分类保留，每类先显示最多 18 张，点击加载更多每次增加最多 36 张；切换 Tab 后重置为首批。当前种子数据初始共 299 张，不再一次生成 2400 张。完整分类页、搜索、官网链接、收藏入口与键盘 Tab 交互保持可用。
4. **请求内复用**：首页把已有 categories 传给首页分区组件；BaseLayout 只读取一次菜单，再传给顶栏和侧栏。菜单没有增加跨请求 TTL，因此保存后下一次请求仍重新读取。
5. **公开索引缓存**：搜索索引、公开站点资料索引、历史词目的地索引按导航快照对象缓存 JSON 序列化结果和 ETag。内容未变化时返回 304、空正文。WeakMap 不阻止旧快照回收。
6. **导航反馈**：客户端路由准备页面时显示非阻塞进度提示，慢请求提示等待，交换页面后清理。保留原加载器与异常，不代理链接点击，不妨碍新窗口、锚点、表单等默认行为。

## 缓存与安全边界

- 索引使用 `Cache-Control: public, no-cache`：允许存储，但使用前须验证，不再叠加浏览器新鲜期。
- 公开索引只有公开站点资料，不包含用户的收藏、访问记录或登录数据。
- 本次没有为 HTML、管理接口、账号接口或个人接口增加公共响应缓存；其鉴权和 `no-store` 规则保持不变。
- 首页仍包含用于本地 Tab 筛选的精简站点 JSON，没有把全量站点重新塞回首批 DOM，也没有自动滚动加载全部卡片。
- 图片继续使用已有的延迟加载与异步解码；没有新增依赖，没有修改数据库表、账号或真实站点记录。
- 此次没有修改线上代理/CDN配置，也没有把开发环境耗时当成生产环境性能承诺。

## 验收命令

```powershell
npm test
npm run typecheck
npm run build
npm run test:build
# 独立启动生产产物、测试后关闭；不写数据库
node scripts/首页性能验收.mjs
# 只读现有 MySQL；加载本地配置但不记录或输出凭据
node --env-file-if-exists=.env scripts/首页性能验收.mjs --mysql
```

性能脚本记录首次请求、5 次连续请求、5 个并发请求、收藏页、管理员登录页，以及三个公开索引的 200/304 响应，输出到 `reports/首页性能验收-seed.json` 和 `reports/首页性能验收-mysql.json`。耗时来自本机生产构建及回环网络，不等于真实公网 FCP/LCP。

构建验收增加两项回归约束：每分类只生成首批卡片，首页 HTML 小于 2 MB。耗时受硬件和数据库网络影响，因此不使用过紧的毫秒阈值制造偶发失败。

## 并发读取与隔离验收

首页并行读取导航与公开菜单；菜单仅合并正在进行的读取，不缓存已经完成的快照。保存菜单成功后使在途缓存失效，避免旧请求覆盖新状态。

多人同时构建时，可使用独立输出目录，避免其他构建清理正在运行的服务文件：

```powershell
node node_modules/astro/bin/astro.mjs build --outDir .astro/performance-build
$env:NAV_BUILD_DIR='.astro/performance-build'
node scripts/首页性能验收.mjs
node --env-file-if-exists=.env scripts/首页性能验收.mjs --mysql
node scripts/检查构建产物.mjs
```

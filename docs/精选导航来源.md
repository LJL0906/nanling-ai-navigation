## 范围与结论

- 核对日期：**2026-09-07**（本地日期，Asia/Shanghai）。所有记录的 `checkedAt` 固定为该日期，不是网页发布日期、版本发布日期或持续监控时间。
- 精选资料独立维护于 `src/data/curated-resources.ts`，顶部下拉与 `/discover/` 共用同一数据源。不改动 2400 条原站点主库，也不改变其中的 `unverified` 状态。
- 最终保留 3 组、每组 6 项，共 18 项；每条提供产品入口、中文描述、用途、官方来源 URL、实际 HTML 标题与核对日期。
- **仅做官方公开资料核对，不是产品功能实测、在线可用性验证或安全保证。** HTTP 200 只说明本次读取获得响应，不能证明登录、付费、地区访问或功能使用正常，更不能标记全站已验证。

## 导航取舍与页面接入

顶部移除重复的“导航”及指向占位页的“文章”“快搜”菜单；首页直达 `/`，我的收藏直达 `/favorites/`。三个下拉按任务组织：AI 效率、创作设计、开发学习，各保留 6 个资源，资源条目直接打开官网。每组底部通往 `/discover/#分组id`；精选页展示全部 18 项的用途、官方来源及核对日期，并加入 sitemap。旧文章、快搜页面保留原路由，不在顶部推荐；侧边栏、完整主库及收藏数据结构保持不变。

## 获取方式与证据限制

1. 已尝试调用 `web.run` 搜索并打开官网，但工具返回空白，没有可读搜索结果或引用编号；这些调用不算来源证据，也不使用空白结果声称核验通过。
2. 随后使用 Node.js 原生 `fetch` 对公开 HTTPS 官方页面发起 GET，跟随正常重定向，在内存中读取 HTML，提取实际 `<title>`、`meta[name="description"]` 和去除脚本/样式后的正文。来源记录使用最终响应 URL；最终采用的 18 个来源页面均取得 HTTP 200 和可读标题。
3. 未执行网页 JavaScript、未登录、未调用模型、未生成图像、未下载软件、未付费，也未绕过访问挑战。豆包和 Qwen 的能力依据仅为官方元描述，Canva 依据官方开发者文档，其它限制逐项列出。
4. 所有能力措辞仅概括实际读到的内容；`useCase` 是据此归纳的使用场景，不是效果承诺。不增加未经证实的免费、排名、最新版本或国内可用性描述。
5. `sourceTitle` 保留获取时的真实页面标题，因而可能含官网自带的版本或价格文案；这些文字仅用于识别出处，不是本导航的产品承诺。标题与页面内容可能随后变化。
6. 未保存第三方网页完整快照，没有生成长期可追溯的抓取归档；下表保留 URL、标题、读取方式、证据摘要与限制。重新维护时应重新读取官网，确认后再更新日期。

## 数据契约与离线测试

- 导出 `CuratedResource`、`ResourceGroup` 两个接口，以及 `RESOURCE_GROUPS: ResourceGroup[]`。
- 固定分组顺序：`ai-work`、`creative`、`dev-learn`；标签依次为 AI 效率、创作设计、开发学习。
- 每条记录包含 `id`、`name`、`url`、`description`、`useCase`、`sourceUrl`、`sourceTitle`、`checkedAt` 八个字符串字段。
- 在项目根目录使用 Node.js 24 原生 TypeScript 导入与 `node:test` 运行：

```powershell
node --test scripts/精选导航.test.mjs
```

测试不安装或导入第三方库，也不联网。覆盖分组 ID/标签/图标、每组数量、总数 18、字段完整性、HTTPS、ID/URL 唯一性、日期及文档来源记录；通过这些结构测试不代表外部站点可用或安全。未增加依赖或改动 package.json。生产产物检查另验证 `/discover/` 返回 200、18 张卡片与来源齐全、三组下拉的官网链接和分组锚点正确、占位入口移除及 sitemap 收录。

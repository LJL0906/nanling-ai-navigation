# 菜单与静态数据入库

> 后续已完成菜单管理闭环：`nav_menus` 由后台维护，前台与接口共用数据库读取层。最新用法见《菜单接口与管理说明.md》。下文保留首次入库阶段的过程记录；`nav_settings` 仍仅完成入库。

## 本轮范围

本轮完成菜单接口开发前的数据准备，不改页面样式、不实现管理端增删改。

- 侧栏：从统一分类库及现有适配层生成菜单，保留默认顺序、图标、分类路径和首页锚点；同步底部设置入口。
- 顶栏：以当前 `RESOURCE_GROUPS` 为准，保存首页、精选分组、资源外链、查看全部、收藏入口。
- 用户区：保存收藏、历史、设置及通知入口。
- 相关配置：站点信息、热门搜索词、展示用户名、分类筛选、首页筛选规则、旧精选视觉配置、精选资源完整元数据。
- 不上传环境变量、密码、令牌、浏览器收藏/历史及个人菜单排序。展示用户名只是现有 UI 配置，不等同于真实登录用户。
- 本地站点图标文件及映射继续作为静态资源维护，不把图片二进制写入数据库。

## 数据表

| 表 | 用途 |
| --- | --- |
| `nav_categories` | 一级分类原始数据、稳定 ID、slug 和顺序 |
| `nav_sites` | 站点原始数据、分类关联和顺序 |
| `nav_menus` | 菜单 ID、父子关系、位置、类型、名称、链接、图标、默认顺序、启用状态和补充信息 |
| `nav_settings` | JSON 配置快照，供后续配置读取接口接入 |

菜单 ID 与分类 ID 分开；同一个入口可出现在不同区域。父菜单先插入，数据库外键保证父子引用有效。分类菜单保留分类路由信息，同时保存实际使用的首页分区锚点，不改变现有点击行为。

正则筛选规则保存为模式字符串和 flags，而非直接序列化 RegExp；后续读取时需显式还原。

## 执行命令

```powershell
# 只读连接检查
npm run db:check

# 只对导航空表进行首次初始化；不会覆盖已有站点
npm run db:migrate -- --apply
npm run db:import -- --apply

# 离线预览菜单与配置，不连接数据库
npm run db:sync-menus

# 显式创建菜单/配置表并初始化
npm run db:sync-menus -- --apply

# 只读逐项对比数据库与当前静态源，并验证页面适配结果
npm run db:verify-static
```

`db:sync-menus` 不是持续覆盖式同步：空表初始化；两表内容完全一致时无操作；已有数据与静态种子不同则拒绝执行，不更新、不删除。后续运营修改应通过专门的管理接口处理。

建表采用 `CREATE TABLE IF NOT EXISTS`，MySQL DDL 会隐式提交，因此表创建不属于可整体回滚的导入事务。数据写入前取得数据库互斥锁，检查 InnoDB 引擎，然后使用参数化 INSERT 和事务；写入失败回滚并释放锁。菜单与配置作为一组初始化，不接受只填充一张表的残缺状态。

## 首次入库阶段的运行时边界（历史记录）

`NAV_STORAGE=mysql` 控制分类与站点读取。菜单和配置入库不代表前端已消费 `nav_menus` / `nav_settings`：本轮保留原有菜单生成方式，后续菜单接口与服务端组件应共用菜单读取层。

侧栏当前会读取分类仓储，因此分类切换 MySQL 后可反映数据库分类；顶栏精选、用户入口及站点配置仍从现有源码读取。不要把修改 `nav_menus` 后页面立即变化作为本轮验收条件。

本地连接按用户确认使用 `MYSQL_SSL_MODE=disabled`，不依赖 CA；此设置不改变项目默认严格 TLS 行为。未将凭据写入本文档。

## 启动

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

已有 `.env` 时不要覆盖。开发服务器只用于受控开发环境，不要将 Vite 开发端口暴露到公网。

需要管理入口时，生成强随机令牌并在本地 `.env` 填入 `ADMIN_TOKEN`：

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

令牌没有默认值。为空、过短或不合规时，管理 API 返回 503；错误令牌返回 401。不要在聊天、URL、Git 或 `PUBLIC_` 环境变量中保存真实令牌。

修改环境变量后重启服务。若 Astro CLI 提示已有开发进程，请在确认该进程由自己使用后执行 `npm run dev -- stop`，再运行 `npm run dev`；不要终止其他并行任务的进程。Node 的 `--env-file-if-exists=.env` 加载本地配置，平台注入的环境变量优先。

## 生产运行

```powershell
npm run validate:data
npm test
npm run typecheck
npm run build
npm run test:build
npm start
```

- 服务端入口：`dist/server/entry.mjs`。
- 客户端资源：`dist/client/`。
- 部署需保留 Node 运行环境及生产依赖，不可仅上传 `dist/client`。
- 不再支持将此构建直接作为 GitHub Pages 静态站点部署。
- 本地 `.env.example` 默认 `HOST=127.0.0.1`、`PORT=4321`；容器或平台若需要监听所有接口，应设置 `HOST=0.0.0.0`。
- 正式环境通过 HTTPS 反向代理提供服务，配置进程守护、请求速率及请求体大小限制。当前令牌入口不含分布式限流或多用户权限体系。
- `npm run preview` 用于本地检查；生产使用 `npm start`。
- `npm run test:build` 会选择空闲回环端口、临时生成测试令牌、启动并停止自身 Node 进程，不修改用户数据库、源数据或真实 `.env`。

## API

所有接口当前只读；非支持方法返回 405。框架的同源安全检查可能在请求进入接口前拒绝跨站请求。

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | 健康状态，明确返回数据库尚未连接 |
| `GET /api/categories` | 分类列表与站点数量 |
| `GET /api/sites` | 站点分页、搜索及分类筛选 |
| `GET /api/sites/{id}` | 通过稳定站点 ID 查询详情 |
| `GET /api/admin/status` | 管理状态与统计，需要 Bearer 令牌 |

查询示例：`/api/sites?q=AI&category=ai&page=1&pageSize=20`。

- `category` 使用路由 slug，如 `search-engines`，不是内部分类 ID `search`。
- `page` 默认为 1；`pageSize` 默认为 48，上限 100。
- `q` 最大 200 字符；匹配名称、别名、描述、域名、标签和原始分类。
- 超出最后一页返回空数组与真实总量；非法分页返回 400。
- 未知站点或分类返回 404。
- 返回结构：`{ data, pagination? }`；错误结构：`{ error: { code, message } }`。
- 公开 API 不返回来源记录对象、环境变量、数据库连接字符串或异常堆栈。
- 不配置通配 CORS；API 及管理页面响应 `Cache-Control: no-store`。

## 管理入口

访问 `/admin/`，输入 `ADMIN_TOKEN` 验证后可查看数据库状态、分类/站点统计，以及只读站点表格。

令牌只存在当前页面内存，请求时放入 `Authorization: Bearer ...`。不会写入 localStorage、sessionStorage 或 Cookie。退出、刷新或离开页面会清理当前会话。

站点与分类本身是公开导航内容；管理令牌保护运行状态接口。未接数据库时不提供新增、编辑、删除按钮，不把操作写入 JSON 或临时内存伪装成持久化。

## 数据库接入点

```text
Astro 页面 / API
        ↓
src/lib/data.ts — getNavigation()
        ↓
src/server/navigation.ts — 选择仓储实现
        ↓
src/server/repository.ts — 统一异步契约
        ↓
src/server/seed-repository.ts — 当前只读种子
```

MySQL仓储与初始化工具已提供；通过 `NAV_STORAGE` 显式切换来源，不让每个页面自行连接数据库。初始化步骤以《MySQL接入说明.md》为准。

需确认：

1. 数据库类型及版本（例如 PostgreSQL / MySQL）。
2. 主机、端口、数据库名与 SSL 要求。
3. 使用专用账号及最小必要权限。
4. 是否空库、是否允许建表、是否已有生产数据。
5. 部署平台及连接网络限制。

敏感密码建议直接填入本地 `.env` 或部署平台 Secret。正式建表、迁移及导入 2400 条数据前需要明确目标库和写入授权，本轮未执行这些操作。

# 通知后端与提交归属说明

## 当前协作状态（2026-09-07）

用户最终确认：提交入口**强制登录**。新请求在读取 body、查询分类、限流及 OSS/数据库写入前检查会话；无 Cookie 的匿名请求直接 401，有 Cookie 的请求必须经过真实 `requireUser(request)` 会话核验。匿名空对象也是 401。有效登录账号由服务端绑定 `nav_submissions.user_id`，仓储再次拒绝空 owner；body 不允许伪造 `userId`、`owner` 等额外字段。历史匿名仍可审核，但不猜测归属、不生成私人通知。

## 三类通知与接口契约

- `site`：站点新增或删除，全体可见。事件 body 保留公开站点名称与 URL 快照（删除后仍可辨认），不复制提交 payload、备注、联系人、邮箱、图标对象 key 或审核原因。
- `submission`：提交成功（`pending`）、审核通过（`approved`）、驳回（`rejected`），只投递给数据库 `user_id` 指定账号。成功与审核结果的 body 保留提交名称与 URL 快照，审核结果提供 `reason`。旧匿名不猜测归属、不生成私人通知；新匿名已禁止提交。
- `announcement`：管理员即时发布的系统公告，全体可见。标题和正文是纯文本，由展示端使用 textContent 或框架默认转义。

`GET /api/notifications?kind=all|site|submission|announcement&page=1&pageSize=20`

默认 `all`，page 最大 1000000，pageSize 为 1–100；重复、未知和非法参数返回 400。响应：

```json
{"data":{"items":[{"id":"UUID","kind":"site","title":"新增站点","body":"已收录站点：示例站点\nhttps://example.test/","createdAt":"2026-09-07T00:00:00.000Z","status":"created","siteId":"site-id"}],"total":1,"page":1,"pageSize":20,"user":null}}
```

`status/reason/siteId/submissionId` 为可选字段；announcement 项额外返回 `revision`。`user` 为 `{id,username}` 或 null。匿名 `all` 只见公开消息；`submission` 必须登录，否则 401。列表 SQL 的 COUNT 与 SELECT 均限定 `visibility + kind + recipient_user_id`，不是读全表后 JavaScript 过滤；同一 REPEATABLE READ 事务读取总数与分页。

公告接口 `/api/admin/announcements`：

| 方法 | 输入 | 输出 |
|---|---|---|
| GET | `page/pageSize` | `{data:{items,total,page,pageSize}}` |
| POST | JSON `{id?,title,body}` | `{data:{id}}`，立即发布 |
| PUT | JSON `{id,title,body,revision}` | `{data:{id}}`，正文标题更新，保留原发布时间 |
| DELETE | JSON `{id,revision}` | `{data:{id}}`，删除公告 |

标题 1–200 字，正文 1–5000 字，请求流上限 16 KiB。管理员 Cookie 写请求同源校验；Bearer 复用已有 CLI 鉴权。不存在公告 404，同编号异内容或版本冲突 409，无效 JSON/字段 400，非支持方法 405，存储未就绪 503。PUT/DELETE 仅操作 announcement/public/无 recipient 的记录，不允许修改站点或私人通知。

### 公告幂等与并发版本

- `revision` 为 `SHA-256(JSON.stringify([id,title,body]))` 的 **64 位小写十六进制**字符串，不包含发布时间。公告列表（公开通知及管理员列表）均返回此字段，其他类型不返回；UI 应原样保存并传回，不自行生成。32 位、63/65 位、大写、缺失或非字符串一律 400 `INVALID_REVISION`。
- PUT 必须 `{id,title,body,revision}`；DELETE 必须 `{id,revision}`。服务端在事务内锁定公开公告行后重新计算并比较版本，过期返回 409 `ANNOUNCEMENT_CONFLICT`，不覆盖、不删除；刷新后由管理员重新确认。
- POST `{id?,title,body}` 保持即时发布。UI 每份新草稿生成固定 UUID id，超时重试复用同一 id 与原内容。服务端先 INSERT，唯一键冲突后以 `FOR UPDATE` 当前读检查：同 id、同规范化标题与正文返回原 `{data:{id}}`，不更新原内容和创建时间；异内容返回 409，不覆盖。未提供 id 时每次生成新编号，无法保证跨请求幂等。
- 幂等比较为精确文本比较（沿用 trim 校验），不依赖数据库大小写不敏感排序规则。站点、私人通知或非公开公告占用同一 id 不可被当作重放或修改目标。
- 不新增数据库列或迁移；内容版本不记录修改次数，改回完全相同的 id/title/body 会得到相同 revision。PUT/DELETE 成功后须刷新列表获取当前 revision。已成功 DELETE 的重试为 404。

## 内容事务接入

不创建重复站点删除 API。沿用现有管理员鉴权 `/api/admin/content`，站点删除 JSON `{kind:"sites",id,revision}`；现有乐观版本校验与最后一条保护不变。

- `content-store.ts` 后台新增站点：站点插入和全体新增事件同事务。
- `content-store.ts` 后台删除站点：清理 `nav_user_records` 中的收藏及历史记录、删除站点、写全体删除事件同事务。
- `submission-publish.ts` 审核发布：新站点插入和全体新增事件同事务。
- `mysql-submissions.ts`：登录用户提交保存 owner 和私人成功事件同事务；审核状态、发布及私人审核结果同事务。
- 内容维护与审核发布共用 `nav-submissions:publish` 命名锁；审核记录保留终态，删除站点不会重置提交状态。重复审核不能再次发布已删除站点。
- 通知插入失败会回滚对应站点或审核操作，不存在成功保存却丢通知的降级。缓存仅在成功 commit 后失效。

公开事件不携带提交编号或审核原因。通知表不设置站点/提交外键，避免站点删除导致历史事件丢失。

## 幂等与历史匿名

新 MySQL 请求键按 `user:<server-user-id>` 进入 SHA-256 身份域，生成稳定 UUID 形状的提交编号及带域摘要。**请求键不再等于返回的提交编号**，客户端重试必须使用原 Idempotency-Key，不能以返回 id 代替。不同账号使用同一请求键不会互相读取或重放，新匿名请求直接被拒绝；同域同内容重试只保存一次。同域内容变更返回 409。

数据库 owner 是权威字段，不信任 JSON payload 中声称的用户；历史匿名 user_id 保持 NULL，不以邮箱、IP、备注或当前会话归属。旧请求键与新域摘要不兼容，因此部署前在途旧客户端重试可能形成新待审记录；审核 URL 去重仍会阻止重复发布。请在维护窗口暂停写入并让旧客户端刷新、重新提交，勿自动回填 owner。

旧文件 save/review/idempotency 工具保留给迁移及离线回归，通过明确命名的 `createLegacySubmissionHandler` 使用私有目录。生产 API 只使用 `createSubmissionHandler`，强制会话校验并拒绝 directory 配置，始终使用 MySQL 账号与通知事务。旧离线入口不是 HTTP 路由，不能用于接收新用户提交。

## 增量迁移（默认不连接数据库）

先完成现有站点、账号、个人记录和提交基础迁移，并备份数据库。不要运行清库、全量同步或覆盖导入来部署本功能。

```powershell
# 只预览，无数据库连接
node scripts/迁移通知与提交归属.mjs

# 管理员检查后显式应用；本次已获授权并执行成功
node --env-file-if-exists=.env scripts/迁移通知与提交归属.mjs --apply
```

迁移检查 InnoDB 及基础表，持有独立迁移命名锁；仅在缺失时添加 nullable `nav_submissions.user_id`，创建 `nav_notifications` 和唯一 event_key/分页索引。不会清库、更新历史 payload 或回填 owner；可重复运行。

注意：MySQL DDL 隐式提交，不能整体回滚，ALTER 可能等待元数据锁。建议停写维护窗口先迁移再部署。遇到已有列/表结构冲突，迁移停止而非自动改类型、去重或删除；可能部分成功，修复后可再次显式 --apply。生产请求不会自动建表。seed 模式或未迁移时返回明确 503，不返回伪持久化成功。

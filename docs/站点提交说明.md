# 站点提交、MySQL 审核与 OSS 附件

## 当前流程

**登录普通用户账号 → 前台提交 → 服务端校验 → 上传图标至 OSS（可选）→ MySQL `nav_submissions` 保存 pending → 后台审核 → approved 与正式站点发布同事务提交 / rejected 保留理由。**

生产 API 默认且仅使用 MySQL，不依赖 `NAV_STORAGE` 的 seed 回退，不再向 JSON 目录写入新记录。未配置 MySQL、表未初始化或连接失败时返回错误，不假报成功、不回退文件存储。前台要展示新站点，导航读取须配置 `NAV_STORAGE=mysql`（当前本地配置如此）。

旧文件 helper 仅供离线工具和旧数据迁移使用；提交处理器拒绝文件写入模式，公开路由不接受 directory 参数，也不根据环境变量切回 JSON。

## 提交接口

`POST /api/submissions`，`Content-Type: application/json`，必须同源 Origin，并携带有效的普通用户登录会话。原有六个字段均为字符串，未使用的传空字符串；备注 `remark` 选填，未知字段拒绝。

```json
{
  "categoryId": "ai",
  "customCategory": "",
  "name": "示例站点",
  "url": "https://example.com/",
  "iconUrl": "",
  "iconData": "",
  "remark": "站点特色或推荐理由，仅供审核参考"
}
```

- 已有分类 id 与自定义分类必须二选一；自定义分类最多 50 字。已有分类从当前导航仓储校验，发布前再次核对数据库。
- 名称 1–100 字。URL 仅绝对 HTTP/HTTPS，最多 2048 字，禁止 URL 凭据、内部空白或控制字符；不抓取用户提供的 URL，不保证网站可用性。
- 备注最多 500 字，支持多行并规范换行，拒绝非法控制字符。空备注与未传等价；备注保留于审核记录，不公开到导航卡片描述。
- 图标 URL 与上传图标最多选一项，可都空。上传使用 PNG/JPEG/WebP/GIF Base64 Data URL，严格小于 1 MiB，检查规范 Base64、类型签名等，不允许 SVG。这不是完整图片解码或病毒检测。
- 请求最多 1.5 MiB，按实际流式字节限制；仅有效 UTF-8 JSON，不支持压缩体。

数据库提交确认后返回 `201`：

```json
{ "data": { "id": "UUID", "status": "pending" } }
```

错误为 `{ "error": { "code": "...", "message": "..." } }`，不返回数据库/SDK 原始异常。400 参数错误，403 来源错误，409 幂等或审核冲突，413 体积超限，415 格式不支持，429 限流，502 OSS 失败，503 数据库或配置不可用。

## 数据表与初始化

`nav_submissions` 使用 InnoDB，包含：

- `id` UUID 主键（有幂等键时等于该键）。
- `request_digest` SHA-256 摘要；旧记录无摘要时允许 NULL，但不可当作成功幂等重放。
- `status`：pending / approved / rejected。
- `payload`：JSON 保存完整提交字段、备注、OSS 对象标识、审核理由/人/时间及发布编号。
- `created_at`、`reviewed_at`：毫秒时间；状态/时间/编号分页索引。
- `published_site_id`：批准并发布生成的正式站点 ID；旧已批准未发布记录为 NULL。

复用现有 MYSQL_* 和 TLS 配置。首次部署先执行：

```sh
node --env-file-if-exists=.env scripts/迁移站点提交.mjs migrate
```

只创建缺失的待审核表，不覆盖分类、站点或菜单。DDL 不在普通请求路径执行；已有表结构变更需单独版本迁移。数据库账户需对待审核表拥有 SELECT/INSERT/UPDATE 权限；发布还需对分类/站点表拥有 SELECT/INSERT 权限及使用命名锁，建表仅部署账户需要 CREATE 权限。

## 后台审批与发布

入口 `/admin/reviews/`，接口 `/api/admin/submissions` 复用 Cookie 会话或 ADMIN_TOKEN Bearer 鉴权。GET 支持 status、page、pageSize，默认 pending、1、20；PATCH 内容为 `{id,status,reason}`，结果只允许 approved/rejected，审核理由必填 1–1000 字，管理员来自服务端会话。

- 审批通过：先获取数据库发布命名锁，再开启事务锁定提交行；校验分类、查重 URL，写入 `nav_sites` 并将待审记录改为 approved、保存发布 ID，在同一事务中提交。任何一步失败全部回滚，记录仍 pending。
- 自定义分类：精确同名复用；缺失则在同一事务中新建。稳定 ID/slug 使用 `submitted-<提交UUID>`。新分类可在全部分类页浏览，不自动创建独立的自定义后台菜单项。
- URL 查重规范主机大小写、默认端口，忽略片段/尾斜杠，保留路径大小写与查询。已存在同 URL 返回 409，不创建重复站点，也不留下空分类。
- 拒绝：只更新审核状态、理由、人和时间，不发布。相同结果/理由重试幂等返回；不同决定返回 409。
- 发布站点保留 `unverified`，审批通过不是在线检测或内容安全认证。备注不用于公开描述。
- 图标仍遵循原有前台白名单策略：来源地址保存在站点 payload，私有 OSS 对象不改为公开。目前新上传来源图标不会自动作为公开图片加载，卡片可使用首字兜底；后续可另接受控图片读取服务。
- 旧 approved 记录迁移后只保留历史，不自动追认发布；`published_site_id` 为空明确表示未发布，不能把历史审核结论误认为已上线。

## 防重复与 Loading

前台首击立即提交，800ms 防连击；请求期间锁定表单/提交/关闭，显示阶段文字与旋转图标。分类加载合并重复请求、最多等待 10 秒；提交及响应体最多等待 45 秒，失败恢复操作并保留输入，超时说明结果未确认，不自动重试。

相同内容重试使用相同 `Idempotency-Key` UUID，修改内容或成功后开始新提交换 key。完整刷新不保留表单/key。

MySQL 主键约束及 `GET_LOCK('nav-submit:<UUID>')` 使同数据库不同 Node 进程共享互斥：同 key 同摘要返回已提交 ID，不重复上传或新增记录；不同内容返回 409。发布另用 `nav-submissions:publish` 锁，始终持有至事务结束后释放；释放失败销毁连接。不得通过其他写入路径绕过发布锁。

数据库幂等支持连接同一 MySQL 实例的多进程；不等于登录会话、限流已分布式化。登录和请求限流仍是单进程方案（每地址 10 分钟 5 次，新提交/参数失败计数），公网建议网关追加分布式限流、容量监测和超时。Origin 检查不是机器人身份认证。

OSS 与 MySQL 不是跨系统事务。OSS 上传成功后进程崩溃或数据库保存失败，可能遗留孤立对象；不贸然自动删除，以免提交结果不确定时删除已引用图片。需定期核对对象 key 与数据库后清理，不承诺跨崩溃恰好上传一次。

## 旧 JSON 数据迁移

切换前停止旧版本写入，备份数据库与私有文件目录。使用 `NAV_SUBMISSIONS_DIR` 或显式目录指定旧源；默认 `.data/site-submissions`（相对进程工作目录）：

```sh
node --env-file-if-exists=.env scripts/迁移站点提交.mjs check
node --env-file-if-exists=.env scripts/迁移站点提交.mjs import
# 指定其他旧目录
node --env-file-if-exists=.env scripts/迁移站点提交.mjs import /absolute/legacy-directory
```

先校验所有文件，再事务导入；发现旧锁/临时文件、无效内容或数据库同编号不同内容时拒绝，绝不覆盖更新后的审核记录。同编号完全相同则跳过，可重跑。所有状态、备注、原图标数据、审核信息与有效幂等摘要原样保留；不自动上传旧 base64、不自动发布历史 approved。不删除或移动源文件，确认后自行归档。生产新写入不读取该目录。

## OSS 配置

```dotenv
OSS_REGION=oss-cn-beijing
OSS_BUCKET=wx-koi-accounting
OSS_ACCESS_KEY_ID=轮换后的RAM访问密钥ID
OSS_ACCESS_KEY_SECRET=轮换后的RAM访问密钥Secret
OSS_SECURITY_TOKEN=
```

仅服务端环境变量，不用 PUBLIC_ 前缀。HTTPS、V4 签名、15秒超时；可选临时 Token 需配套且不自动续期。新对象在 `site-submissions/YYYY/MM/<UUID>.<扩展名>`，正确 MIME、private ACL，不改变桶权限。正常提交需要业务前缀写权限及设置私有ACL所需权限，清理需相应 DeleteObject 权限，不开放整桶管理。已在聊天或非密钥渠道出现的凭据应轮换，重启 Node 服务生效。

## 图标上传防滥用

上传文件在调用 OSS **之前**，通过 MySQL `nav_upload_quotas` 原子预扣配额；同一 MySQL 写入实例上的多个 Node 进程、服务重启共享计数。部署新代码前执行下列幂等迁移（不会清空已有配额）：

```sh
node --env-file-if-exists=.env scripts/迁移站点提交.mjs migrate
```

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `OSS_UPLOAD_ENABLED` | `true` | 设置 `false` 紧急关闭新文件上传 |
| `OSS_UPLOAD_IP_DAILY_LIMIT` | `10` | 单 IP 每日上传尝试次数 |
| `OSS_UPLOAD_IP_DAILY_BYTES` | `5242880` | 单 IP 每日 5 MiB |
| `OSS_UPLOAD_DAILY_LIMIT` | `200` | 全站每日上传尝试次数 |
| `OSS_UPLOAD_DAILY_BYTES` | `104857600` | 全站每日 100 MiB |
| `OSS_UPLOAD_TOTAL_LIMIT` | `2000` | 部署计费以来全站累计尝试次数 |
| `OSS_UPLOAD_TOTAL_BYTES` | `1073741824` | 部署计费以来全站累计 1 GiB |

- 次数和容量必须同时满足，容量按校验后实际解码字节计量；单文件仍须严格小于 1 MiB，仅接受校验签名的 PNG/JPEG/WebP/GIF。
- 全站固定最多两个并发上传，第三个立即返回 429；达到任一配额也返回 429，不调用 OSS。配置无效、配额数据库不可用或锁结果不明确返回 503，禁止绕过。
- 日额度以数据库 UTC 日期分桶（北京时间每日 08:00 切换）。累计额度不自动清零；从此功能部署时开始计费，不包含历史 OSS 对象。提高累计上限前应核对实际存储与费用，不要删除累计行绕过限制。
- OSS 失败、结果不明确、上传后保存失败均不退还已扣额度，避免借失败重试持续写对象。已经成功保存的相同幂等键重放不重复上传、不扣额度。
- 无图标、在线图标地址不上传 OSS、不占上传额度；紧急关闭文件上传不影响这两种提交。前端仍保留防连击、提交互斥和 Loading，并展示上传额度提示。
- IP 来自服务端适配器 `clientAddress`，不会读取客户端伪造的 `X-Forwarded-For`。IPv4/IPv6 规范化后哈希存储；未知地址共用保守桶。反向代理部署若只提供代理地址，用户会共用配额，须正确配置可信代理；不能直接信任任意转发头。IP 哈希不是强匿名，不公开配额表。
- 多 IP 机器人仍可能耗尽额度，使正常用户暂时无法上传；该方案限制应用上传量，不代替网关限流、验证码、请求体限制或 DDoS 防护。持有 OSS 密钥的直接请求不受应用配额约束，须配合最小权限、密钥轮换及费用告警。
- 不自动删除 OSS 对象或重置配额。孤立对象须核对数据库引用后处理；模块提供的历史日桶清理 SQL 仅供运维审查后执行，保留累计桶，当前未接自动清理任务。

专项回归：`node --test scripts/上传配额.test.mjs scripts/MySQL提交仓储.test.mjs scripts/站点提交.test.mjs`，使用模拟数据库和 OSS，不上传真实文件。

## 登录与提交人归属

- 点击提交按钮先检查登录，未登录唤起账号弹窗；登录或注册成功后继续打开站点提交浮层。发送提交前再次校验会话，过期时保留输入并提示重新登录。
- 服务端在读取提交内容、上传 OSS 和保存数据前调用 `requireUser`，未登录返回 401。管理员登录不能替代普通用户登录。
- 提交人只取服务端会话中的用户 ID，写入 `nav_submissions.user_id`；请求体不接受 `userId`、`user_id` 或通知接收人字段。相同幂等键不能由另一个账号重放。
- 待审提交和该用户的私有提交成功通知在同一事务中写入；审核结果通知绑定原提交人，用户在「通知 → 我的提交」查看。历史匿名记录保持 NULL，不猜测归属、不回填给当前账号。
- 旧数据库部署前执行 `node --env-file-if-exists=.env scripts/迁移通知与提交归属.mjs --apply`，增量补齐用户归属字段、通知表和索引，不清空现有记录。
- 门禁回归：`node --test scripts/提交登录门禁.test.mjs`，覆盖匿名先拦截、会话身份透传、伪造归属拒绝、登录失效不保存。

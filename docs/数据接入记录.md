# 全量数据接入记录

日期：2026-09-07

## 本次范围

按《数据接入方案》第一阶段接入统一站点库，不实施完整二级分类映射、收藏、访问记录或在线站点审核。

- 内容源：`src/data/导航数据.json`，18 个分类、2400 条去重后站点。
- 适配入口：`src/lib/data.ts` → `src/lib/adapt-navigation.ts`。
- 原始 CSV、JSON 快照继续留存，不重新采集、不再次清洗或改写网址。
- 全部 `unverified` 站点正常接入；“未验证”不等于“失效”，也不代表已通过安全审核。

## 数据与展示规则

1. 分类关联使用统一数据的 `category` / 分类 `id`；页面路径使用分类 `slug`，例如 `search` → `search-engines`、`news` → `community`。
2. `description` 映射为现有组件的 `desc`；空描述使用站点名称及分类生成兜底文案。
3. 稳定 ID、别名、域名、原始分类、标签、来源及验证状态保留在构建端模型中。
4. Iconify 图标沿用。远程图片和原始字体图标暂用首字色块兜底，原始图标信息不丢弃、不加载未验证的外站图片。
5. 旧 `sites.json` 仅用于精选顺序、颜色、缩略图样式、首页分区和历史路径识别；不再决定全站数量。
6. 分类页沿用旧精选优先，其余站点保持统一数据顺序；分类归属以统一数据为准，不为保留旧卡片位置改回旧分类。

## 页面范围

- 侧栏、全部分类、Tag 索引、详情页和 sitemap 使用完整分类与站点模型。
- 首页保留原有 5 个分区、28 张精选卡片，不铺满 2400 条站点。
- 分类每页 48 条；首页路径为 `/{category}/`，后续分页为 `/{category}/page/{page}/`。
- 现有 AI、开发、设计的精选 Tab 暂时保留，不把原始来源分类直接暴露为新 Tab；筛选基于完整分类，不受当前分页切片影响。
- 搜索使用 `search-index.json` 静态索引，匹配名称、别名、描述、域名、分类名、标签及原始分类；按页渲染结果，不把完整来源记录下发到浏览器。
- 原有 70 条精选记录的详情链接均保留：未变化的直达，变化的生成静态跳转页。
- 旧 `/entertainment/` 分类入口跳转至 `/media/`；重分类的旧站点详情各自跳转至其实际新分类。
- Astro 的静态跳转输出为 HTML 跳转页；托管平台若需要 HTTP 301 状态码，应另配平台重定向规则，不能把静态 HTML 当作服务器 301。

## 更新与验收

```bash
npm run validate:data
npm test
npm run typecheck
npm run build
```

生产构建会先校验统一数据，失败即中止。校验涵盖主键、路由、分类引用、URL、图标、数量和旧精选对应关系；具体规则见 `scripts/校验导航数据.mjs`。

适配测试检查全量不丢失、ID/slug 映射、首页限制、历史链接迁移和搜索字段保留。数据更新后不应直接修改测试期望以掩盖数量变化，应先核实源数据与统计是否一致。

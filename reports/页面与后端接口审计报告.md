# 页面与后端接口审计报告

审计日期：2026-09-07（北京时间）  
对象：当前工作区源码、`http://localhost:4321` 开发服务、当前 MySQL 数据。  
方式：并行源码审计、只读 HTTP GET、只读数据库查询、纯函数契约验证。没有执行数据库写入、注册、审批、删除或迁移，没有修改业务代码。

## 一、结论

- 当前数据：18 个分类、2400 个站点、52 条公开菜单；健康接口确认 MySQL 连接正常。
- 对 sitemap 地址、补充功能入口及页面发现的站内链接去重后，核验 **2480 个站内地址**：2471 个 200、1 个 301、8 个 302；未发现 HTTP 404/500 或请求失败。
- 另外检查当前公开菜单的 **30 个站内链接**，跟随跳转后均 200，带锚点的目标均存在。
- **明确未实现的页面：2 个**，`/articles/` 与 `/quick-search/`。它们返回 200，但只有“筹备中/开发中”占位内容。
- **功能名实不符的页面：1 个**，`/tags/` 实为分类和站点名称索引，不是真实标签导航。
- **配置闭环缺口：1 类**，`nav_settings` 有数据但无运行时配置读取及管理 API/页面。
- **高优先级契约缺陷：1 类**，后台新增和审批发布站点 ID 与搜索、收藏、历史的数据校验不兼容。当前旧数据尚未触发。
- 3 个固定跳转入口不是死链；登录保护下的后台跳转也不是无效页面。

以上不是“所有功能均已验收通过”：本次没有浏览器逐项点击、登录用户端到端测试及写库测试；外部收录网址未做在线可用性检测。工作区存在其他任务同步修改，结果是本轮观测快照。

## 四、P1：新站点 ID 契约不一致

### 生成端

- `src/server/content-store.ts:120`：后台新增站点生成 `site-UUID`。
- `src/server/submission-publish.ts:73`：审批发布生成 `submitted-UUID`。

### 消费端

- `src/scripts/search.ts:47-48`：只接受 `/^site_[a-z0-9]+$/i`；一个异常条目会令整个索引解析失败。
- `src/scripts/personal-catalog.ts:13-16`：全站个人列表目录也只接受 `site_...`。
- `src/server/personal-validation.ts:10`：收藏、访问等接口只接受 `/^site_[a-z0-9]{1,59}$/i`。
- `src/scripts/personal-api.ts:18-21`：个人数据响应校验仍只接受 `site_...`。
- `src/lib/personal-store.ts:8`：旧本地数据工具同样限制 ID。

### 可复现证据

直接调用 `validatePersonalAction({action:'favorite', siteId, selected:true})`，不写数据库：

| ID | 结果 |
|---|---|
| `site_0c372ce2acdc` | 校验通过 |
| `site-00000000-0000-4000-8000-000000000000` | 400 INVALID_PERSONAL_DATA |
| `submitted-00000000-0000-4000-8000-000000000000` | 400 INVALID_PERSONAL_DATA |

只读查询当前 nav_sites：2400 条 ID 全部仍符合旧格式，因此**不是声称现在搜索已坏**。通知中的已删除 submitted ID 也不能证明当前目录故障。

新格式站点进入公开索引后，可能同时造成：

1. `/search/` 全量索引加载失败，而非仅搜不到新站点。
2. `/favorites/`、`/history/` 全站资料目录解析失败，即使用户只收藏旧站点也可能受影响。
3. 新站点收藏/访问操作被服务端 400 拒绝。

建议优先统一生成端与消费端契约，兼容已有合法 ID，并加后台新增、审批发布到搜索/收藏/历史的回归测试。不要直接改数据库主键来掩盖问题。

### nav_settings 配置缺口

数据库确有 8 个配置键：categoryTabs、currentUser、homeSectionPageSize、homeTabRules、hotSearches、legacySites、resourceGroups、site。

但 `src/server/menu-schema.ts:18` 只有配置表定义；运行时没有配置读取仓储、鉴权配置 CRUD API 或后台配置管理页。站点名、SEO、首页文案等继续来自 `src/config/site.ts:2`，首页每区数量来自 `src/lib/home-sections.ts:4`。直接修改配置表不会使这些页面配置生效。

其中 categoryTabs/homeTabRules/hotSearches 等属于旧快照，不代表已移除的固定热搜仍在使用；currentUser 也不能替代真实会话身份。配置表若定位为初始化档案，这属于待建设能力，不是当前运行故障。

### 仅本地保存，是否补接口需按产品需求决定

- 搜索历史：`src/scripts/searchHistory.ts:1-14`，浏览器共享键，没有账号级隔离和跨设备同步。
- 用户侧栏排序：`src/scripts/sidebarOrder.ts:19-23,43-45`，仅当前浏览器。
- 主题：`src/scripts/theme.ts:18`，设备级偏好可以合理保留本地。

这三项不应因使用 localStorage 就一概认定为错误；要求账号同步时再补偏好存储及接口。
